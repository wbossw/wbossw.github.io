Cap

Writeup técnico de la máquina Cap de Hack The Box.

Sistema Operativo Linux
Dificultad Fácil
IP Víctima 10.129.65.229
IP Atacante 10.0.2.15

1. Comprobación de Conectividad

El primer paso consiste en comprobar la conectividad entre nuestra máquina atacante y el objetivo mediante ping.

wbossw — Conectividad Clic para copiar 
ping -c10 10.129.65.229

La respuesta obtenida confirma que existe comunicación con el objetivo y que no se produce pérdida de paquetes.

2. Enumeración de Puertos

Con la conectividad confirmada, realizamos una enumeración de los puertos TCP expuestos mediante Nmap.

wbossw — Nmap Clic para copiar 
nmap -p- --min-rate 5000 -T4 10.129.65.229

El escaneo identifica tres servicios accesibles:

21FTP

22SSH

80HTTP

Estos servicios proporcionan los principales puntos de enumeración para continuar con el análisis del objetivo.

3. Análisis de la Aplicación Web

El siguiente paso consiste en analizar el servicio HTTP disponible en el puerto 80. La aplicación presenta un dashboard en el que aparecemos autenticados como el usuario Nathan.

Los servicios FTP y SSH no permiten acceso anónimo, por lo que necesitamos obtener credenciales válidas antes de utilizarlos.

También se realizó una enumeración básica de directorios sin encontrar inicialmente ningún recurso que permitiera avanzar directamente en la explotación.

Por ello, continuamos analizando las funcionalidades disponibles dentro de la aplicación web.

4. Identificación de una Vulnerabilidad IDOR

Durante la navegación por la aplicación encontramos una funcionalidad que permite acceder a recursos mediante un identificador numérico incluido en la URL.

wbossw — Recurso Clic para copiar 
http://10.129.65.229/data/2

El identificador 2 corresponde al recurso asociado a nuestro usuario.

Al modificar manualmente este identificador y utilizar 0, la aplicación devuelve un recurso perteneciente a otro usuario.

Vulnerabilidad identificada

La aplicación presenta una vulnerabilidad IDOR (Insecure Direct Object Reference) debido a la ausencia de una comprobación adecuada de autorización sobre el recurso solicitado.

El recurso obtenido corresponde a un archivo PCAP que puede ser analizado para obtener información sobre el tráfico de red.

5. Análisis del Archivo PCAP

Una vez identificado el archivo PCAP, lo descargamos y procedemos a analizarlo mediante Wireshark.

La inspección del tráfico revela comunicaciones sin cifrar. Entre los paquetes capturados aparece una autenticación contra el servicio FTP.

En primer lugar podemos identificar el usuario utilizado:

wbossw — Usuario FTP Clic para copiar 
nathan

Posteriormente encontramos la contraseña transmitida durante la autenticación:

wbossw — Credenciales recuperadas Clic para copiar 
Buck3tH4TF0RM3!

Usuario nathan

Contraseña Buck3tH4TF0RM3!

Disponemos ahora de unas credenciales válidas que podremos comprobar contra los servicios FTP y SSH identificados durante la enumeración.

6. Acceso mediante FTP

Utilizamos las credenciales obtenidas del archivo PCAP para acceder al servicio FTP.

Una vez autenticados, enumeramos el contenido disponible:

wbossw — Enumeración FTP Clic para copiar 
ls

Entre los archivos disponibles encontramos users.txt, que descargamos utilizando:

wbossw — Descarga Clic para copiar 
get users.txt

Una vez descargado el archivo, cerramos la sesión FTP:

wbossw — Salida Clic para copiar 
exit

De vuelta en nuestra máquina atacante, comprobamos el contenido del archivo:

wbossw — users.txt Clic para copiar 
cat users.txt
User Flag a34c116802a8d62f79a500c79c511ec7

7. Acceso mediante SSH

Comprobamos que las mismas credenciales también son válidas para el servicio SSH.

wbossw — SSH Clic para copiar 
ssh nathan@10.129.65.229

La conexión proporciona una shell interactiva como nathan, permitiendo continuar con la enumeración local del sistema y analizar posibles vectores de escalada de privilegios.

8. Escalada de Privilegios

Con acceso al sistema como nathan, el siguiente objetivo es obtener privilegios de administrador.

Durante la enumeración se identifica que /usr/bin/python3.8 dispone de privilegios especiales que pueden ser aprovechados para ejecutar acciones con permisos elevados.

bash — Python 3.8 Clic para copiar 
/usr/bin/python3.8

Al ejecutar el intérprete con dichos privilegios podemos modificar el UID efectivo del proceso y posteriormente iniciar una shell.

python3.8 — Privilege Escalation Clic para copiar 
import os
os.setuid(0)
os.system("/bin/bash")

os.setuid(0) establece el UID del proceso en 0, correspondiente al usuario root. Posteriormente, os.system("/bin/bash") inicia una nueva shell con los privilegios disponibles para el proceso.

Privilegios elevados obtenidos

La explotación permite obtener una shell con privilegios de root.

9. Obtención de la Flag Final

Con acceso como root, accedemos al directorio /root y consultamos el archivo que contiene la flag final.

root — root.txt Clic para copiar 
cd /root

cat root.txt
Root Flag 244aaa67f543561d20a2863d6ea024b8

Con la obtención de la flag de root queda completada la máquina Cap.
